What is ATHENA? Project Overview 
ATHENA is a full-stack algorithm lab that runs 44 real algorithms in a C++ engine, visualizes every 
step, and provides AI-powered explanations — built for DAA learning. 
 
•  Runs 44 algorithms in a real C++ engine (not fake animations) 
•  Shows every compare, swap, and recursive call step-by-step 
•  Big-O Complexity Analyzer — static AST parser + live benchmark curve fitting 
•  Lie Detector — claim a Big-O, system proves you right or wrong 
•  DNA Diff — compares two algorithm traces side-by-side using LCS 
•  Bug Injection + Cache Simulator + AI Explanation via Ollama llama3.1:8b 
 
Built With 
C++20 — Execution engine 
Python / FastAPI — Backend API 
Next.js 14 + Tailwind v4 — Frontend UI (port 3004)

How It Works — System Architecture (3 Layers) 
1   Frontend 
Next.js 14 + Tailwind v4 — port 3004 
10 visualizer types: bar, graph, recursion tree, DP table, hash buckets, chessboard, Huffman tree, Gantt, 
knapsack, string compare. 
Playback: Play / Pause / Step Forward / Step Back / Speed control. 
 
2   Backend 
Python + FastAPI 
12 API routes: /run-algorithm, /analyze-complexity, /benchmark, /simulate-cache, /run-diff, /run-bug, /run-
whatif, /search, /explainstream and more. 
Spawns C++ process via WSL, streams NDJSON trace back to frontend. 
 
3   C++ Engine 
athena_engine binary 
44 algorithms compiled with REGISTER_ALGO macro. 
Emits every step as JSON: step number, type, state, comparisons, swaps.

Challenges / Roadblocks 
• 
NDJSON Stream Volume: Algorithms on large inputs (n > 5,000) emit hundreds of thousands 
of trace steps. Without RLE compression on the C++ side, the stdout pipe became a 
bottleneck. Resolved by implementing emit_rle() that squashes repeated compare-only cycles 
into a single count token. 
• 
Windows Compatibility: The C++ binary uses Linux resource control (rlimit, SIGXCPU). On 
Windows, this required a WSL wrapper invocation layer in tracer_bridge.py. Mac/Linux work 
natively. 
• 
Pydantic v1 → v2 Migration: Several services still use legacy model_validator patterns from 
the original Segment 1 design. Careful interface boundaries were needed to prevent schema 
conflicts between old and new models. 
• 
Missing Algorithms: Heapsort, Dijkstra, and Kruskal are registered in config.py but not yet 
compiled in the engine binary. Calls to these names return UNKNOWN ALGORITHM errors.

Project Outcome / Deliverables 
• 
Fully working Athena v5 — DAA Algorithm Visualizer & Formal Complexity Analysis System 
with a compiled C++ engine, Python API, and React frontend. 
• 
Animated implementations covering all 5 units: Unit I (Binary Search, Tower of Hanoi, 
Fibonacci), Unit II (9 sorting algorithms with swap/comparison counters), Unit III (BFS, DFS, 
Dijkstra, Bellman-Ford, Floyd-Warshall, Kruskal, Prim), Unit IV (N-Queens, Knapsack, LCS), 
Unit V (KMP, Rabin-Karp, Hash Table). 
• 
Runtime Execution Tracer: DAG where every algorithm step is a node; BFS/DFS applied on 
this graph for state replay. Memory high-water-mark tracking for empirical space complexity 
measurement. 
• 
Formal Complexity Analyser: CFG construction → loop nesting depth → recurrence relation 
→ Big-O derivation via Master Theorem, Recursion Tree Method, and Substitution Method. 
• 
ML Support Models trained on C++ benchmark data: Decision Tree Big-O classifier and 
Linear Regression runtime predictor. Validated against formally derived complexity values. 
• 
Lie Detector feature: empirically verifies user-claimed Big-O using SciPy curve fitting and R² 
goodness-of-fit against multiple complexity templates. 
• 
Bug Injection & What-If Analysis: side-by-side diff of correct vs buggy/modified execution 
traces with propagation chain visualization.
